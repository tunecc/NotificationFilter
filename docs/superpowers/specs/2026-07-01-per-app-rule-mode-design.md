# 单应用规则黑白名单模式设计

## 背景

Notification Filter 目前的全局规则和单应用规则都使用黑名单语义：排除规则优先放行，包含规则和正则规则命中后拦截。这个模型无法满足某些应用“只允许指定通知通过，其余全部拦截”的需求。

本设计为单应用规则增加黑名单/白名单模式。模式只作用于每个应用自己的规则；全局规则继续保持现有黑名单语义，并且仍然先于单应用规则执行。

## 目标

- 每个应用可以单独选择黑名单或白名单模式。
- 旧配置没有模式字段时默认按黑名单处理，保持现有行为不变。
- 白名单模式下，包含规则和正则规则表示命中放行，排除规则表示命中仍拦截。
- 设置界面在当前模式下显示清楚的规则名称和说明，避免“包含/排除”语义反转造成误解。
- 导入导出继续兼容旧配置，并在新导出中包含应用规则模式。

## 非目标

- 不改变全局规则语义。
- 不改变全局规则和单应用规则的执行顺序。
- 不迁移底层 `contains`、`exclude`、`regex` 三个规则数组名称。
- 不新增独立的白名单规则存储结构。

## 数据模型

在共享偏好层新增单应用规则模式字段：

```objc
NFRulesModeKey = @"mode"
NFRulesModeBlacklist = @"blacklist"
NFRulesModeWhitelist = @"whitelist"
```

该字段只用于 `AppRules.<bundleID>` 的规则字典。全局规则仍由 `GlobalRulesEnabled`、`GlobalContains`、`GlobalExclude`、`GlobalRegex` 归一化为现有规则字典，但不需要在 UI 或行为上暴露模式。

归一化规则：

- 原始规则不是字典时，返回禁用的黑名单规则。
- `mode` 缺失、类型错误或不是 `blacklist/whitelist` 时，归一化为 `blacklist`。
- 保存单应用规则时写入归一化后的 `mode`。
- 删除某应用规则时删除整个应用配置，包括 `mode`。

导入导出影响：

- 导入旧 JSON 时，旧应用规则会自动补 `blacklist`。
- 导入新 JSON 时，合法 `mode` 会保留。
- 导出新 JSON 时，每个应用规则包含 `mode`。

## 规则引擎

整体判断顺序保持不变：

```text
插件总开关 -> 全局规则 -> 单应用规则 -> 默认结果
```

全局规则保持当前黑名单语义：

- 全局排除规则命中：放行。
- 全局包含规则命中：拦截。
- 全局正则规则命中：拦截。
- 全局无命中：继续进入单应用规则。

单应用黑名单模式：

- 排除规则命中：放行。
- 包含规则命中：拦截。
- 正则规则命中：拦截。
- 全部无命中：放行。

单应用白名单模式：

- 排除规则命中：拦截。
- 包含规则命中：放行。
- 正则规则命中：放行。
- 全部无命中：拦截。

实现时可以抽出内部规则组评估方法，避免把全局黑名单、单应用黑名单和单应用白名单三套流程复制展开。评估结果继续使用 `NFMatchResult`，保留 `matchedScope`、`matchedMode`、`matchedPattern`。

白名单默认拦截没有具体命中规则，需要新增可识别的匹配模式值，例如 `whitelist-default`，用于日志详情展示“未命中白名单所以被拦截”。

现有早退逻辑保持不变：插件关闭、通知文本为空、没有应用 Bundle ID 或该应用规则关闭时，白名单模式不参与判断。

## 设置界面

单应用规则页第一个 section 作为配置区，顺序为：

```text
启用该应用规则    [开关]
规则模式          黑名单 / 白名单
```

`规则模式` 位于启用开关下方。点击该行弹出 action sheet：

- 黑名单模式：命中拦截规则时过滤通知，未命中默认放行。
- 白名单模式：只放行命中白名单规则的通知，未命中默认拦截。

规则列表标题按当前模式动态显示，但底层仍保存到原有规则 key。

黑名单模式显示：

| 底层 key | UI 标题 | 作用 |
| --- | --- | --- |
| `contains` | 拦截关键词 | 命中后拦截 |
| `exclude` | 放行例外 | 优先放行 |
| `regex` | 正则拦截 | 命中后拦截 |

白名单模式显示：

| 底层 key | UI 标题 | 作用 |
| --- | --- | --- |
| `contains` | 放行关键词 | 命中后放行 |
| `exclude` | 强制拦截 | 优先拦截 |
| `regex` | 正则放行 | 命中后放行 |

规则编辑页的 footer、输入提示、扫描生成规则的规则类型分段标题也应按当前模式使用同一套语义文案。全局规则页继续显示“包含规则 / 排除规则 / 正则规则”，因为全局规则仍然是黑名单语义。

## 测试与验收

规则引擎需要覆盖：

- 旧配置缺少 `mode` 时默认黑名单。
- 单应用黑名单：排除放行、包含拦截、正则拦截、无命中放行。
- 单应用白名单：排除拦截、包含放行、正则放行、无命中默认拦截。
- 全局规则仍优先于单应用规则。
- 应用规则关闭时，白名单模式不参与匹配。

偏好归一化需要覆盖：

- `mode` 缺失。
- `mode` 非字符串或非法字符串。
- 导入旧结构后仍可保存和导出。

构建和手工验收：

- 至少运行 `make package-debug-rootless`。
- 如实现改动影响共享偏好或打包路径，再运行对应的 `make package-rootful`、`make package-rootless`、`make package-roothide` 或 `make build-packages`。
- 在 Settings 中检查单应用页：模式选项位于启用开关下方，切换模式后规则标题、footer、输入提示、扫描生成规则标题同步变化。
- 手工验证白名单模式下未命中任何规则的通知会被拦截，并在已过滤通知日志中显示可理解的原因。

## 风险与边界

- 白名单模式默认拦截范围更大，UI 文案必须明确提示“未命中默认拦截”。
- 底层 key 继续叫 `contains/exclude/regex`，实现时必须避免把 UI 标题当作持久化字段。
- 全局规则先执行。如果通知已经被全局包含或正则拦截，单应用白名单不会再放行。
- 扫描生成规则目前只支持包含和排除两类选择，切换到白名单模式时必须显示为“放行关键词”和“强制拦截”，但保存目标仍是 `contains` 和 `exclude`。
